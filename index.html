The real engineering story

Bug 01 — a 12-year-old, still-open Paramiko bug

Legacy Cisco IOS SSH servers don't strictly follow the public-key handshake spec — asking for the signature twice, even after it was already sent. Traced via debug-level analysis and a decade of GitHub issue history. Fixed with ios_compat_patch.py, not a workaround.

Bug 02 — false alerts, every single night

FortiGate re-encrypts fields with a random salt on every pull — real ciphertext, zero real change. Would have buried every genuine alert forever. Fixed with normalization before comparison, verified against an empty diff.

Bug 03 — a 22-character hostname silently broke a fixed-width parser

Adding a second Cisco 3560E exposed a bug this toolkit had been silently carrying: show lldp neighbors's fixed-width Device ID column overflows past 20 characters with no space separating it from the next field. The parser read the Hold-time value as the port instead — no error, just a wrong label on the live diagram. Fixed by shortening the hostname to fit the column.

Bug 04 — the site silently served the wrong content

After deploying this site, the public URL intermittently showed Cherwood Health's page instead. DNS, Cloudflare's cache, the file on disk, and nginx's config all checked out individually correct — the real cause was localhost resolving to either 127.0.0.1 or ::1 depending on the connecting process, and this site's nginx block only listened on the IPv4 address. Whichever loopback path the tunnel happened to use decided which site got served. Fixed by adding listen [::]:80; alongside the existing listener — found the identical gap on a second, unrelated port serving tarunc.com shortly after.

Bug 05 — DNS filtering blocked the domain, twice, for different reasons

The FortiGate's DNS filter redirected this domain to its own block page. A brand-new throwaway test hostname hit the identical block, ruling out anything specific to this project's name. The category grid didn't show an age-based rule either — the exact trigger stayed unconfirmed. What's proven: static domain-filter allow entries fix it, but the GUI silently failed to save them twice; only a CLI write followed by a CLI read-back reliably worked.

Bug 06 — a credential almost shipped hardcoded

The ServiceNow integration's instance password was hardcoded directly in drift_check.py during initial testing, to get the API call working quickly. Caught before it was ever committed to git — once a secret lands in commit history, it stays there permanently unless the history itself is rewritten. Fixed by pulling the value from an environment variable set once in root's crontab, since cron doesn't inherit a shell profile the way an interactive session does.

Bug 07 — a form field that silently refused to change

Advancing the ServiceNow Change Request's state directly via its dropdown did nothing — no error, just no movement. The real cause: ServiceNow's Normal Change model gates state transitions behind an actual approval workflow and a required Assignment Group field, neither of which is obvious from the form alone. Fixed by using Request Approval and working through genuine CAB-style approver records instead of fighting the state field — which is exactly how a real production change model is supposed to behave.
